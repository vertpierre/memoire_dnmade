Glossary

Library [computing]

Set of pre-existing functions that extend the capabilities of a programming language and simplify development.

Source code

Text file written in a programming language, composed of lines of code that define a program.

Compositing

Modification applied to an image or video, whether for colour grading, special effects, etc.

Copyleft

Wordplay in opposition to copyright. A principle that uses copyright law to ensure that derivative works remain free and reusable, by requiring that any modification needs to be distributed under the same conditions.

CSS (Cascading Style Sheet)

Means cascading style sheet. A language used to visually style and lay out XML or HTML documents, typically web pages.

UX (User experience)

A field similar to what might be called ergonomics, defining the user’s interaction with their environment.

Fanzine

Independent publication, often experimental, originally made by enthusiasts of a subject for other enthusiasts.

Fork

Denotes the creation of new software from another project’s source code, whether from an older modified version or the latest one, adapted over time. This is found mainly in free or open source projects, since their sources are open and modifiable by everyone.

HTML (HyperText Markup Language)

Means hypertext markup language. A markup language inspired by SGML syntax, used to form the structure of web pages that are displayed. It is one of the foundational technologies of the Web.

HyperText

A document that is usually part of a set of documents linked by hyperlinks.

HyperLink

A textual element that acts as a reference in a hypertext document, pointing to another part or another document.

Vector image

Image created from geometric shapes and thus from mathematical paths. This approach contrasts with raster images made of pixels. The advantage of vector images is that they do not lose quality regardless of size and can also be very light in file size.

Raster image

Image based on a grid of points, each with its own colour; we then speak of pixels. It is the most commonly used format, as it is the image format of cameras and digital cameras.

UI (User interface)

It generally goes hand in hand with user experience and defines the visual part with which the user interacts.

Internet

Large-scale computer network, with origins attributed to Tim Berners-Lee in the early 1990s, from which various applications derive such as the Web, email, videoconferencing systems and peer-to-peer sharing.

JavaScript

Programming language mainly used on the Web to create scripts that add interactivity.

Licence

Text defining the legal framework for the use of a work, as well as its ownership.

Software

Set of instructions forming programs executed on a computer.

Free/libre software

Sometimes shortened to libre when referring to the philosophy behind it. Defines a type of software, a practice and a social movement aimed at giving the user full freedom. It upholds four fundamental freedoms:

  • • To run the program as you wish.
  • • To study how it works and modify it, which requires transparent access to the source code.
  • • To redistribute copies for accessibility.
  • • To distribute modified versions of the code to share knowledge.

Open source software

Defines a type of software similar to free software, but where the philosophical and ethical dimension is often set aside in favour of the technical efficiency of software development. This can lead to programs with hybrid licences, mixing libre and proprietary. This diversion of libre ethics is often heavily criticised by the free software community.

Proprietary software

The opposite of free software: programs that restrict the user’s freedom, whether legally through restrictive licences or technically by limiting access to the source code. They are also called proprietary or “user-subjugating” software by Richard Stallman and others in the free software community, as they harm the user’s freedom.

SaaS (Software as a service)

A business model that usually requires a subscription, where software is not installed on the client’s computer but runs on remote servers.

Version control software

Also called DVC (Decentralised Version Control). The aim is to record different versions of code when the author needs to, without duplicating it, using backup files.

Kernel [computing]

Software system made up of low-level programs that communicate with the computer’s components. It is required for an operating system to function, as the operating system builds its application layer on top of it.

P2P (Peer-to-peer)

A system for exchanging information directly from user to user, without going through a third party such as a centralised server.

DTP (Desktop Publishing)

Refers to the creation of documents for print using digital programs rather than the manual and industrial processes previously used. DTP is closely linked to WYSIWYG, which has made it the dominant way of creating in design today.

Visual programming

Differs from text-based programming made of lines of characters. Visual programming is done by assembling graphical elements. It usually consists of boxes containing functions, which can either be nested (blocks) or connected by links (nodes) to produce the desired result.

Polyfill

An extension of a programming language, commonly used on the Web, that enables browsers that do not yet or no longer support certain features and standards to use them.

SGML (Standard Generalized Markup Language)

A markup language used in the documentation and publishing industries. It served as the basis for HTML.

SVG (Scalable Vector Graphics)

A file format for storing vector images, based on XML syntax.

OS (Operating system)

Set of programs that manage the resources used by the computer through application software intended for the user.

Node-based system

Works on the same principle as visual programming. In 3D or visual effects software it can be used to modify the geometry of a 3D or 2D object, create textures, do compositing, etc.

W3C (World Wide Web Consortium)

In 1994 Tim Berners-Lee introduced the W3C as an international consortium, an organisation that manages the standards used by the Web, such as HTML, XML, SVG, CSS, etc.

Web

Short for World Wide Web (WWW), literally: global web. It is based on a HyperText system that creates links between different texts and is part of the Internet computer network.

Web2Print

This term refers to web applications that allow the design of creations intended for print. Generally, these applications let the buyer customise the ordered product.

WYSIWYG (What You See Is What You Get)

Defines programs whose output (printed or digital) matches what is visible on screen. Although WYSIWYG existed since 1974, it took until 1984 and more powerful computers such as the first Macintosh for it to become widespread.

XML (Extensible Markup Language)

A formal standard that defines the syntax rules of certain markup languages, derived from SGML. It aims to be simpler to use and better suited to the web than SGML.

Abstract

This research explores free/libre software and the philosophy behind it through the field of graphic design. I asked whether it could lead to a more ethical design practice. My thesis shows that the practice we inherit as designers is not always one we have chosen, which can lead to forms of design that are not centred on the human. As Nolwenn Maudet explained, The stagnation of the design tool landscape led to the progressive invisibility of design software in designers’ practice. Software made invisible in this way, such as Adobe Creative Cloud, still shapes specific practices even when we are not fully aware of it.

Adobe also has complete control over the proprietary software it distributes and over the files that software generates. To find a way to avoid this loss of control over our tools and practice, I dug into the philosophy of free software, centred on user freedom. I examined dissertations, projects and software, interviewed users about their practice, and questioned my own. Although free software is often met with bias and preconceptions, I found that it can give designers greater control over their tools and files while leading them towards a more ethical practice.

Introduction

In 1984 Apple released the first Macintosh¹ under Steve Jobs’s direction, a tool that would revolutionise personal computing and kick off a wave of digital creation, with the emergence of powerful software, including the Adobe suite², which would quickly become the designer’s single set of software tools. Thus, for more than 30 years, the graphic designer has used the same kinds of digital tools and seems to make do with them.
Yet in their practice they must constantly question the media and tools chosen for a given task and result, since these raise technical, aesthetic and sometimes ethical questions.

Also in 1984 the GNU project³ was born, initiated by Richard Stallman, who challenged the user’s growing lack of control over computing tools. He laid down the fundamental rules of free software⁴ in opposition to so-called proprietary software⁵, and opened up a new sense of freedom in computing. Free software or at least open source⁶ has by now proven itself and become widely adopted, not least thanks to the Web⁷ and Linux⁸.

On the design side, many free software tools have appeared but have often been labelled unfit for professional use because of their interfaces⁹, and face widespread prejudice. In practice, the graphic designer mostly uses proprietary software such as the Adobe suite, often for convenience. But their use implies practices (often tied to profit) that do not reflect the designer’s mission, which is, in my view, to give form to information and make it accessible to all.

Faced with ever greater dependence on proprietary tools, to what extent can free software allow the graphic designer to rethink their practice ?

Through the study of theoretical reflections and more practical objects, as well as my own experience and that of other practitioners of the free/libre software world, I have sought the strengths that free software could contribute to rethinking our graphic creation tools, and how a free/libre approach could drive a more open graphic design practice, putting sharing and accessibility at the centre.

Taking back control of one’s tools

Software dependency

The designer constantly questions the graphic means they deploy, but the question of software is often ignored. The monopolistic Adobe Creative Cloud suite¹⁰ is generally the only option, with a production chain that drives all designers’ practices, as Anthony Masure¹¹ points out: The graphic chain thus gradually narrows to a single actor who concentrates all power in a pyramidal scheme.¹²

It is a creative factory focused on productivity in the creative process, right down to finding clients via the Bēhance¹³ platform.

This logic leads to tools where the user is confined to moving within an environment that appears simplistic, where everything seems easy to use and no longer prompts them to question their usage.¹⁴ Although Quentin Creuzet¹⁵ is speaking here of the Web user, the designer operates in the same environment through Adobe, which offers products that seek to remove all difficulty in favour of efficiency and—in their view—creativity, leading the designer in practice to stop questioning their tools.

A form of dependency is created, and from the very training they receive, where the Adobe suite is favoured. The designer is no longer master of their tool; they use it by default because it has become the norm. It thus seems necessary to turn towards more open tools so as not to lock oneself into a logic of productivity¹⁶.

Unsuitable tools

Beyond a dependency problem, Adobe’s tools no longer always seem suited to the designer’s practice. Since their creation they have evolved very little, with only minor interface or user experience changes¹⁷.

Designer Mitch Paone¹⁸ reports the limitations of After Effects¹⁹ for some of his projects, which led him to create his own tools giving him more control in generative typographic animation.²⁰ Graphic designer Nolwenn Maudet²¹ reports similar findings. Software is modelled on manual practices that predate DTP²² and separates creativity from tool use. This led her to imagine new forms that offer more freedom and to explore programming.²³

Many graphic designers now turn to software development to gain full control over the creative process. For example, Paged.js²⁴ enables layout from Web languages, while other free software such as Blender²⁵ use a node-based system²⁶ linking programming and interface more closely. Despite this freedom, development requires specific knowledge and the loss of a more natural interaction²⁷ that emerged with the WYSIWYG²⁸ revolution.

Towards more open software

This attachment to unsuitable tools is all the more harmful because only Adobe software can open their files (based on proprietary formats), leading everyone to depend on a subscription to the creative suite.

As OSP²⁹ put it—a collective that works only with free tools—[…] it would be acceptable to pay for something like an Adobe Creative Cloud subscription if the file formats were free and documented [...]³⁰ These file formats, over which users have no control, limit their options: they not only force reliance on one type of software but also raise important questions about the longevity of their data, leaving users at Adobe’s mercy.

By contrast, on the free software side, every format created is thoroughly documented. In most cases, files are based on open standards such as the SVG³¹ format in Inkscape³², which, as well as offering a WYSIWYG approach, allows direct editing of the file’s source code.

Reusable and adaptable creations

If it seems necessary to take back control of our digital tools through software that is truly suited to the graphic designer’s practice and based on open formats, it would make little sense without rethinking our relationship to the ownership of data. Since software implies a practice, turning to the free/libre software world implies using and producing files under a free licence.

This approach is found mainly in typographic creation, for example Velvetyne³³, a digital foundry that offers a wide variety of atypical typefaces. It is fully aligned with libre ethics, with complete freedom to use and modify the fonts; the only requirement is to credit the author. Inter³⁴ is also a fully reusable and adaptable free typeface. It is mainly utilitarian, designed for optimal reading on interfaces, in the tradition of the International style.

In the age of Internet, where everything is reused and remixed, we share without necessarily considering the legal framework of our uses and productions. To support this right to reuse and adaptation, the choice of licences applied to our creations should be a conscious one.

Shared knowledge

The use of more open software and files should not be limited to personal use but should also lead to sharing knowledge and the sources of creation, which raises questions of archiving.

Through Fragile Forge³⁶, Raphaël Bastide³⁵ shares the software he develops. Their files and source code are also available thanks to the version control software³⁷ Git³⁸, via the collaborative platform GitLab³⁹. Both are widely used by developers to keep different versions of code, create forks⁴⁰, and share creations. OSP clearly understood its relevance in design by building the Visual Culture⁴¹ project on Git. It provides a worked visual overview of images and changes applied to a project, enabling the sharing of the sources of their creations within a clear archive⁴².

The designer’s practice should thus be oriented towards sharing data, which can be useful for everyone’s learning.

Design for the human

If design involves sharing and disseminating knowledge, it also involves questioning how it is used.

As Quentin Creuzet points out, certain misuses of the Web, reinforced by the graphic designer’s work, lead to a space where surveillance capitalism reigns⁴³. Anthony Masure thus asks us: Where then does the designer’s work stand? Do they work for the user or for the profit that private firms wish to derive from this space?⁴⁴

Graphic design is indeed a powerful tool that uses visual language to reach the individual. Do we create to help the user, or to steer them towards a predefined action? Since the graphic designer’s role is, in my view, to bring information to the fore and make it accessible, it seems to me necessary to rethink our practice and move towards design for the human rather than exploiting users for other ends.

Conclusion

It therefore seems that the designer’s practice can be at odds with the intentions of proprietary software publishers. They create systems that subject the graphic designer to sometimes unsuitable software, making them forget the possibility of access to other tools, or even preventing such access through closed formats on which they depend.

It therefore seems urgent to move towards more open software that involves practices closer to the designer’s work, and thus towards free software, which offers users complete freedom through the philosophy on which it is based and the licences that follow from it. It allows us to rethink our practice by moving towards a form of graphic design based on sharing, where information is accessible to all.

Could there be a paradigm shift similar to the computing world turning towards free software, or at least open source? Does this not imply moving towards a design where code becomes the norm for greater freedom?

Although many free/libre alternatives exist, I have found in my research that their fields of application and uses are rarely well presented. It would seem to me worthwhile to create an awareness-raising platform around these various tools and the graphic productions associated with them, because there is an issue of education and information— without which these software tools will remain in the realm of utopia.

Raphaël Bastide

[Interview translated from French, trying to keep as much as possible the original meaning]
Interview conducted by videoconference on Jitsi [free software for videoconferencing] with Raphaël Bastide, professor of art and graphic design, on 1 November 2021 at 15:00, lasting 1h15.

The following transcript is a reduced and edited part of the full exchange. [see the website for the complete exchange]

Could you give a brief overview of your background?

I studied both technical and artistic subjects. I started at the IUT [University Institute of Technology] in Bordeaux, which was called Services et Réseaux de Communication. It had a small graphic design component that I really liked. I then went on to a graphic design school in Toulouse that probably no longer exists; it wasn’t a very good school. But I learned a lot on my own and discovered the social Internet of the first social networks between 2000 and 2005, where artists and graphic designers were starting to make work for Internet.

So that influenced their own practices and I was very interested. I soon discovered Net.art [generally interactive works conceived by and for Internet]. I found it really compelling—it was really art and still is, art made for Internet as an artistic medium.

I explored all of that further, doing personal research in parallel with my graphic design studies. Then I also discovered free software and decided to go to the ERG [École de Recherche Graphique] in Brussels, where I did a Master’s in Digital Arts with a typography option. That allowed me to keep exploring this side of graphic design, in digital art.

You publish almost all your work under a free licence. What is your intention behind that?

Today, it’s more of a non-choice in the sense that I no longer choose to distribute under a free licence; it’s rather something I do naturally. It’s part of my working methodology and also a way for me to contribute to something larger, since I use a lot of things that were made by others.

So in principle I’ll redistribute what I do to anyone interested.

So it’s more about being part of a flow that interests me, and the characteristics and methodology that go with it suit me perfectly, suit my way of working. Everything to do with versioning [creating versions with version control software], licence choice, collaboration when it exists, documentation—all of that interests me deeply.

I might even say I document for others so as not to have to document for myself; it’s a kind of working discipline that lets me work efficiently.

I think I may have had a slight self-discipline problem to begin with that is mostly addressed by the idea that others will see what I do, or that I myself will see it in the future. That is, there’s a version of me in ten years who will come back to what I made and say Good thing I noted that! or Oh well, that’s not there, etc.

What do you make of there being more software diversity in accounting than in graphic design, as Franck Adebiaye points out?

I’d say I know one but not the other, unlike Franck, so I couldn’t say why there’s no major player in accounting, even if I have an idea. But in any case I’m sad to see that there are indeed software tools that have completely dominated the market and practices of graphic design, and I understand why. Nothing was in place to counter them. Now that’s something that tends to be a bit less true. My sense is that the Adobe suite is having a bit more trouble keeping its market position.

Still, among the books in a bookshop today, I think 99.9% were designed with InDesign [proprietary software for DTP launched in 1999 by Adobe]. So it’s quite significant, and I think what’s most interesting in Franck’s quote is that it exists at all—that is, that this lack of diversity apparently bothers no one.

What interests me in that is that there are people, a handful, who want to say no.

The editorial forms in the broadest sense that we produce today come from the same black boxes that are corporate products and aren’t questioned. Black boxes are fine—they’re everywhere. We drive them, we have them in our pockets. But here the problem is that there’s very little criticism of this and diversity is sorely lacking. And we see that as soon as there’s a bit more technological diversity, it allows for greater cultural and aesthetic breathing room. It allows for emancipation and also for giving a voice to minorities. All of that is very connected. The software we use has an impact on both the productions and the producers.

What do you think about more generic free graphic production tools such as Scribus [free software for DTP] compared to others like Paged.js [free software for DTP based on web development]?

I see it as a gradient. That is, there are several levels, several types of software. There are as many interfaces as interface creators. The team behind Inkscape and the team behind Paged.js are not at all the same. They don’t have the same software culture, don’t have the same stack, so the toolchain isn’t the same either. The age of the program isn’t the same and the users aren’t the same.

Inkscape [free software for creating vector images], for example, is software aimed at a very broad public, whereas Paged.js is aimed at developers who will need to call it as a library in a program.

I find this granularity of differences very healthy because there are also many different practices and uses. I’m interested in engaging with all of that as an author of software or programs, or whatever. I’m interested in playing at doing very dry things, or on the contrary working on interfaces that smooth things out for users in the right way by offering things they already know.

Actually, it would be too sad to have only one type of software. And anyway, many people say that free software is bad software, or that libre forms are ugly forms.

There’s some basis for that in that people make ugly things with free software, but maybe it’s because people who work with free/libre software are already convinced they can only do that—it’s the snake biting its tail. But thinking about it, that argument no longer really holds. What I’m saying is that a huge number of very interesting things have been done with free software like the Firefox browser [free browser developed by the Mozilla Foundation since 2003]. Firefox doesn’t produce ugly formats. Firefox enables the development of all the website interfaces we see today.

So there’s no software that produces ugly forms—only individuals who produce ugly forms, and I’d even say only individuals who judge those forms to be ugly. Personally I’m very interested in working with these so-called ugly forms because they belong to a certain folklore and they create a history not only of free software but more broadly of the history of the interface, of web design history, of online communities.

[Final conversation around my thesis question]

Another area to dig into is libre graphic design practices. There are things emerging that can’t be done with proprietary software. There are plenty of others that can be done with proprietary software with no problem. But free tools, interfaces, custom tools have an aesthetic impact on certain practices that has never been mapped, to my knowledge. It could be interesting to see to what extent free tools and methodologies can influence aesthetic choices. Can we identify a scene? Can we find particularities that are clearly definable, clearly associated with free software, and thus map and find the players?

The first thing that comes to mind is the acceptance and foregrounding of error, but of course there’s more. There’s digital vernacular typography, for example. There’s something interesting there—the question of layout with web2print tools, fanzines. What traces can software like Inkscape or Paged.js leave—are there graphic traces? Maybe it’s a bit long to explore, but I think it’s very interesting.

There’s also the question of spreading the culture of free graphic design. There have been things—Libre Graphics Magazine [annual magazine on free graphic design creation, no longer published since 2015], Libre Graphics Meeting [annual international meeting on free graphic design tools]. There have been blogs, there have been things, but there’s no energy that brings it together. We try to do it with PrePostPrint [label and website that highlights publications and resources based on experimental free creations]; it remains very niche on layout and publishing, but we have a Twitter account, we post things when there are interested students.

What’s missing is something that federates around the dissemination, culture and possibilities of free graphic design. Because there are things—blogs that talk a lot about Gimp [free software for creating raster images], Inkscape—but they teach you to make ladybugs in vectors.

It’s not uninteresting, but it lacks something that interests students, teachers, professional graphic designers.

Nolwenn Maudet

[Interview translated from French, trying to keep as much as possible the original meaning]
Interview conducted by videoconference on Jitsi with Nolwenn Maudet, interaction designer and design researcher, on 4 November at 09:00, lasting 45 minutes.

The following transcript is a reduced and edited part of the full exchange. [see the website for the complete exchange]

Could you give a brief overview of your background?

I’m Nolwenn Maudet, I’m an interaction designer, design researcher, and senior lecturer at university. I have more of a product design background and was trained at the École Boulle with a BTS and DSAA. I later realised I was more interested in digital media. So I wanted to complete my studies after my DSAA with a Master’s that I completed at UTC Compiègne, which was dedicated to user experience.

That Master’s opened the door to the world of research for me, thanks to many very interesting teachers, and I discovered a lab that did what was called human–computer interaction, which led me to do my thesis in computer science but which was in reality more linked to design.

Then I went to do what’s called a post-doc—a research stay in a non-permanent researcher position at the University of Tokyo—before obtaining a teaching and research position at the University of Strasbourg, where I still am.

You published your thesis under a free licence. Is that something you apply regularly in your projects?

Yes, it’s something that’s really important to me. With the digital in particular, I think the old ideas of intellectual property as they applied in design no longer really make sense. On the contrary, I think that today it’s much more interesting to share what we do as designers, and especially when we’re researchers. It seems aberrant to me that sometimes research publications aren’t accessible to everyone, given that it’s taxpayers’ money—there’s no reason for knowledge not to be accessible to all.

Even beyond that purely financial reason, there’s also a more ideological reason. For me, knowledge is something that should be accessible to everyone. It only has benefits, so yes, it was really important that my thesis be accessible in open source. If I hadn’t done that, the only people who would have had access to this research would probably have been large companies like Google, Facebook, Adobe who could afford to pay for access to the often Anglo-Saxon libraries in the research world, whereas I was much more interested in the French-speaking community. I think using that licence was the only way to make it accessible.

What is your relationship to free/libre practice in the rest of your work?

I’d say it revolves mainly around the licences I assign to my work rather than the tools. I’m a strong supporter of free/libre practice, but paradoxically I use little free software. For everything to do with production, I think I use almost only tools under proprietary licence.

Despite that, I sometimes use free tools, as in one of my recent projects with my colleague Thomas Thibault [digital designer and co-founder] of the BAM collective [a design studio that promotes the autonomy of the designer and user in their productions]. Not putting it under that licence would go against everything I stand for in my projects themselves, since most of them are about “empowerment”—that is, giving back tools and ways for everyone, designers and users, to reappropriate the digital world.

That’s really important to me, and free licences in particular are vital for that.

I regularly collaborate with the BAM collective, within which there is a real approach to using free tools but it’s not always easy. For example, a choice that was made and that I share was to abandon the Adobe suite in favour of a suite called Affinity [suite of 3 proprietary software tools similar to the Adobe suite].

And I think we’re more and more numerous on that point, even if it’s not the best solution since they’re not free tools. Despite that, this use has the merit of helping a non-Adobe solution exist and of reducing a monopoly.

Besides, I use fewer and fewer software tools in my personal practice. The Affinity suite is useful from time to time, but day to day I almost only use programming. The use of open languages such as those of the web means that yes, I actually use free tools a large part of the time.

What do you make of there being more software diversity in accounting than in graphic design, as Franck Adebiaye points out?

That was also my observation, and it is one reason I wanted to write my thesis. I find it extremely sad and I think there are several factors involved: historical, political, contextual, but also the fact that for a long time this question of the tool was not at all a concern for designers. They treated the tool as a given without really asking the question, without wondering if the tools used could have an impact on their practice. It was Adobe or nothing.

That said, I loved my studies and the way I was taught design. But the tool was really a blind spot, which affected me a lot. When I started to look into the subject, I could see the richness of designers’ practices—who, being creative by nature, always go beyond the tools.

We have a tool that is exactly the same, but there isn’t a single designer who uses it the same way as another or creates the same thing, since by definition in our jobs we reinvent things, we try to invent our own process. So creativity is much more on the designers’ side than on the tools’ side.

That aspect of design practice led to this problem: we always started from the same base without ever questioning it, which is still a problem today, it seems to me. So when I started my thesis in 2014, everything was very fixed in terms of Adobe-type software.

On the other hand, there was a huge boom in 2015–2017 in software in the UX [user experience] and UI [user interface] disciplines, but we’re now seeing exactly the same monopolisation process with Figma [software specialised in UX and UI design]. All of that seems to me almost linked to a Taylorisation [systematisation of production for maximum output] of design professions that makes it seem more practical and efficient to rely on software rather than giving people more freedom.

What do you think about more generic free graphic production tools such as Scribus compared to others like Paged.js?

I think it’s really great that free/libre practice and this diversity exist, and I think there’s real interest in moving towards programming, which offers power, freedom and agency that are quite incredible and enjoyable as a designer.

That said, and it’s a bit of a regret of mine, something I tried to say in my thesis is that I find it sad that we so quickly abandoned software [with graphical interfaces] because we don’t think the same way when we think through programming as when we think through graphical interfaces—we don’t visualise things the same way and we don’t interact the same way.

I’m not saying one way is better than the other. I think both are fascinating. We can do different things with both, but I’m really convinced that programming alone still has severe limitations—there are things it doesn’t offer in a natural way, an ease that we find in software with graphical interfaces. I find it a shame that there is so little current exploration of graphical interface mechanisms that would offer new ways of doing layout, for example.

Paged.js

Enhanced publishing software

Paged.js is a free and open source JavaScript library that makes it possible to create print-ready PDF layouts directly from a browser. This library is thus similar to DTP software.

This project is aimed mainly at publishing production and was initiated in 2017 by Adam Hyde [creator behind many projects promoting open source in publishing, through new ways to rethink publication]. He leads technical projects, builds platforms and methodologies within the Coko [Collaborative Knowledge] Foundation to support the production and publication of documents and knowledge in open source.

Today, Julie Blanc [graphic designer currently working on a thesis in ergonomics and graphic design, questioning in particular layout and automation in graphic design] is one of the most important contributors to this project, especially through her expertise in CSS.

Paged.js is thus a JavaScript library that extends the possibilities of the Web’s base languages, such as CSS, to adapt them to the production of print layouts. This language extension is called a polyfill, since it allows browsers that do not yet support new standards to support them.

The project is part of an approach rooted in the spirit of the Web, since the new functions added to CSS follow the paged media standards published by the W3C.

Thus, with this library and by learning some of its new functions, it is possible to create documents for publication within the browser itself, using standard web languages such as HTML and CSS. With a little practice, any graphic designer with knowledge of website creation can create publishing objects from a fanzine to a full-length book, the kind of object Paged.js was designed for, in a browser. The project therefore aims to create a completely open system, also accessible via GitLab, but above all a very well documented website, both for setting up a project end to end and for the fine-grained details of the library.

Links to free/libre practice

What is interesting here is that Paged.js allows us to completely rethink how we do layout, using fully open standards and formats. Moreover, the fact that the library is based on web languages—that is, programming languages—also supports various experiments using generative elements as well as animations. Paged.js has in fact been taken up by PrePostPrint, which is both a label and a website whose aim is to promote graphic objects and resources based on experimental, free and well-documented creations. It aims to bring together various pieces of software and projects using experimental publishing techniques and to help make their projects and tools more accessible.

This library also makes it possible to rethink publication in a more modular and open way, as Nicolas Taffin [graphic designer and publisher] points out; he works at éditions C&F [of which he is co-founder with Hervé Le Crosnier]:

The author and the designer work together on the book, each has their own files. In view of the layout, each can decide to change things—the author can cut text for example, the designer can move elements, adjust their layout rules locally—while avoiding modifying the author’s file to do so.

By each working directly on their own files, which are then combined in the final layout, it is possible to create a book where the author’s texts and the designer’s modifications can be applied in real time thanks to a server hosting the files, as Nicolas Taffin currently does within the Interventions collection, using NextCloud here [file hosting and collaboration platform that can be self-hosted. It is a free alternative to Google Drive].

Thus, with a few ideas and extensions, Paged.js can become a real-time publishing platform, which is made possible in particular by its grounding in a free software approach. Furthermore, Paged.js also highlights the question of file longevity. By contrast, while software such as InDesign [proprietary software for DTP launched in 1999] from Adobe [publisher of proprietary creative software] uses proprietary file formats whose workings are completely opaque, Paged.js offers file formats supported by almost any plain-text editor, since it is based on open programming languages. Even if this is an extreme case involving web languages, it nonetheless seems to me that free tools have this strength of being based on standards, and at least on open file formats, making it possible to have creations that do not depend on a single tool—creations that can be reused over time.

Visual Culture

Visual versioning

Visual Culture is a free/libre project that uses Git [decentralised version control software developed by Linus Torvalds, creator of Linux], a kind of version-archiving system for the source code of a project, here applied to visual material, launched by the OSP collective [Open Source Publishing, a collective of graphic designers who work exclusively with free and open source tools] at the start of 2014 in the form of an unsuccessful crowdfunding campaign.

Moreover, this project was developed in-house within the collective and already existed before the campaign launch, and still exists today as an integral part of their website. Some features that were meant to be developed through the crowdfunding campaign are not present. Other systems such as Git already existed before, with more or less similar approaches, but the most powerful among them were often very expensive and offered a closed, centralised system. Git managed to stand out through a decentralised, peer-to-peer approach. This fits fully with the spirit of the Web, especially as Git is a free project and thus completely open.

But as its history shows, this project was initially created for and by developers. In practice it only tracks textual changes within a file. Even today, collaborative platforms based on Git such as GitLab or GitHub [both are proprietary collaborative text management systems using Git, but GitLab offers a self-hostable open source version] do not effectively display the different versions of a visual production. Visual Culture therefore builds on this Git base and aims to offer software to visualise the creation process, archive and exchange data and changes in projects that have a strong visual component such as graphic design. Ideally, we could then visualise the different versions of a file, which would make it possible to understand and explore the history of these digital objects as a form of archiving. Once the file is modified, these changes can be shared with collaborators and also with the public, in a spirit of openness specific to the free/libre software world. Today, even though the crowdfunding did not succeed, this project continues to live on through the OSP website.

For each OSP project we can find a history of changes, visually accessible in the form of a long timeline where each change is represented by small notes, with more or less space between them depending on the time elapsed between two modifications. Although we find a visualisation of image files within the projects, there does not seem to be a history of these file versions, and the notes on the timeline do not display images.

Links to free/libre practice

Visual Culture is therefore a tool that seems to me complementary to a graphic design practice that aims to be more open, since it is a project that enables collaboration and in-depth study of the files produced by creators, by presenting the history of images, typefaces and the choices that led to applying these various modifications. This project offers another approach to graphic design, in which the notion of sharing knowledge is at the centre of creation, as it is rooted in the dynamics of free software. It aims to share collaboration methods widely used in the development world and to make them accessible to image professionals.

This working method, which is now very widespread in the programming world, seems to me to represent an interesting path for graphic design practice, since more than a versioning system, Visual Culture is part of an open approach that makes it possible to pass on graphic design practice and how it works, and to open knowledge to all. It also seems to me that such a tool could better present the different versions and evolutions of a file or project to a client, better adapt a design by giving access to its older versions, all in a simplified way with a powerful archiving system.

A more open tool

This doctoral thesis in human–computer interaction was completed in 2017 by Nolwenn Maudet [interaction designer and design researcher], who works with the BAM collective [a design studio that promotes the autonomy of the designer and user in their productions]. The thesis thus takes an academic, almost scientific tone, with an approach strongly based on practices found in scientific culture, with various tests offered directly to designers. Nolwenn Maudet explores both the substance and the form of graphic production software, and questions how these software tools work by contrasting them with the way designers create and use tools today. She highlights other ways of imagining the graphic designer’s software, especially through development and tools that offer more freedom. Today’s software, and in particular the Adobe Creative Cloud suite [suite of various proprietary creative software from Adobe], has evolved very little over the last three decades and has become so omnipresent today that we tend to stop questioning it: it thus becomes invisible.

This thesis therefore addresses a gap between the day-to-day practice of graphic designers and the current graphic design tools on offer. Thus, traditional design tools such as the Adobe suite separate creativity from tool use, prioritising values like efficiency and ease of use, which would allow more time to be creative. The thesis is divided into two main parts, with 13 chapters in total. In the first part, Nolwenn Maudet studies designers’ practices through digital tools that allow a study of their behaviour in daily life or directly in the software they use. These studies are based on 4 principles used by graphic designers: colour, alignment, layout and collaboration.

In the second part, once these practices are defined through an in-depth study of graphic designers’ behaviour and needs, the author looks at the creation of design tools that support these major principles and their exploration by designers. Nolwenn Maudet thus argues for rethinking design software, to transform it by bringing development practice closer to design and linking it to the graphical interface. Software development is indeed a practice that many designers turn to in order to regain greater freedom in their design. With a view to rethinking one’s relationship to one’s practice, and thus to the tool, this notion of the invisibility of the tool seems to me very interesting. The designer’s practice constantly comes back to questioning the tools that can serve them for a task as much as for a given result, as one would question the choice of using a laser printer rather than a risograph. The tool, especially for the designer, is not something that should be taken for granted; it raises aesthetic, technical and sometimes ethical questions that are part of the creation process and should not be taken as given.

Links to free/libre practice

Furthermore, in her thesis Nolwenn Maudet presents the creation of these tools based directly on graphic designers’ practice, and the way in which they reappropriate these tools by adapting them to a more personal practice. This reappropriation comes through a greater ability to adapt one’s tools. They can in fact evolve through their flexibility, making it possible to create powerful tools. This way of imagining the graphic designer’s tool as malleable fits fully with hacker ethics, but also with the free/libre approach, and is close to current free/libre tools, which all have this capacity for adaptation through programming [directly in lines of code or through visual programming].

Another interesting fact mentioned only at the end of the site: this thesis was written entirely with free software, using the web format with HTML, and the printed thesis was exported using HTML2PRINT [software for DTP developed by OSP, which uses web languages and converts an HTML page into a printable document. It is in some ways similar to Paged.js]. Furthermore, in the same vein as Anthony Masure, this thesis was published under the licence CC-BY-NC-SA [licence Creative Commons, a very adaptable type of licence linked to open source. Here CC = Creative Commons, BY = attribute the author’s name, NC = non-commercial, SA = share under the same licence], further integrating this document into a free/libre practice through the use of specific alternative software that makes it possible to move from Web format to print.

The designer and their tools

Design et humanités numériques is an essay written from March 2015 to May 2017 by Anthony Masure, a design researcher. The book was published in 2017 as the first in the Esthétique des données collection at éditions B42 [known for its works devoted to design and art], and also as the publisher’s first text under a free licence. This text is thus an essay that questions and connects design and digital humanities, for a collection that was originally called 404. Work on this essay came from a proposal by Nicolas Thély [researcher and professor in art, aesthetics and digital humanities] who was on Anthony Masure’s thesis jury and suggested he write an extension of his thesis.

This book takes two forms: a printed form that draws on part of his thesis and extrapolates from it across 7 chapters that can be read independently, and a website with complementary content. This online section provides free access to complementary content such as images, descriptions and analyses of objects that were cut from the printed version for reasons of space and bulk, in line with a desire for accessibility—economic accessibility in particular but also due to its reduced format. The site makes it possible to find images that complete this content, and the site was also to offer a year later a version of the work under a free licence in full.

Through this essay, Anthony Masure tries to get us to step back and consider the links that can exist between design and the stakes of what is called “research and development”. He then links design to digital humanities, which could be defined as the association of scholarly practices in literature and the humanities with digital materials of all kinds, whether software or hardware.

Thus, what in his view brings these two fields together is that digital humanities, like design, have been facing digital processes for many years. It is logical that these two fields meet, both in production and in the transmission of knowledge, through digital materials. Within the essay he develops the fact that the field of research and development is now subject to profitability demands, and that design often has, at least in common parlance, the aim of making people buy.

He thus wishes to question this view, with an idea of design that could instead thwart these expectations of profitability that can come to standardise our environments [we can see this especially through operating systems such as Android and iOS, which are more and more similar with each iteration, or even through web sales sites that always use the same structures]. Design should stand in opposition to this current evolution of our landscape and should start reflections aimed at reinventing our living frameworks, at questioning anew what exists with the contribution of the digital, rather than only adapting it. Thus, within Anthony Masure’s research, design does not only have the role of giving form to produced content, but can also re-question the very way of producing knowledge, whether through its valorisation, its graphic forms, or even the different media on which it appears.

Anthony Masure thus defends the idea that design has more than a simple value of exposition or ergonomic need, which can lead to more and more norms. It has a capacity to transmit knowledge through approaches that can be more experimental, especially within Digital Humanities. As he notes from the end of his introduction, there is room for another form of design that does not follow the sole industrial logic.

Links to free/libre practice

For what follows, I focused mainly on the third chapter, entitled “The injunction to creativity and innovation”, from page 57 to 73. Here Masure looks at the place of productivity and the term innovation in the field of design, especially in software, and at what could shift habits and expectations that we impose on design or that design sometimes imposes on itself. What he fears is a one-directional design oriented toward efficiency, but which risks being increasingly standardised. On the contrary, he would like to move towards a design that activates a plurality of possibilities, that is not one-way. He seeks questions more open than the sole aim of being a production machine, something clearly highlighted by the Creative Cloud Suite, which functions as an injunction to creativity, to the need to be creative.

In the introductory first part, Masure raises many questions, including these: Where then does the designer’s work stand? Do they work for the user or for the profit that private firms wish to derive from this space? (p. 57). I find these questions interesting because they raise a fundamental question about design that I see as closely linked to free/libre practice. Free/libre software gives complete access to knowledge of one’s tool and allows us to do what we want with the program, all with the aim of giving the user total freedom. This emerged in opposition to “user-subjugating” software [which deprive the user of the freedoms defined by free software], whose primary aim may be to use users rather than serve them.

The second part continues to raise this question of service, through this quotation: He who is in the service of is not free; he seeks, says Montaigne, to enrich himself. (p. 60). He returns to the use of simplified interfaces, in fact touted by companies, but which in reality are an experience thought through from end to end in order to absorb the user’s time. Is that really the designer’s work? In practice, as with software, it seems to me that the designer must above all create with the aim of serving the user, and not use them for profit-driven goals, as with Instagram and its attention-capturing design. The aim is to make the practice as transparent as possible. In the third stage, Masure presents the fundamental differences between innovative design and inventive design. The term innovation does not historically come from the field of design. It comes rather from management, economics, patents, the secrecy of technical processes. In practice, if design goes too far in this field, it risks closing in and no longer being interesting for us as citizens.

We should instead create for the human, making creative work for life (p. 67), and indeed so-called creative software plays an essential role, since the term itself indicates a knot between the notions of programmes (implying modelling) and creativity (which cannot occur without deviation). (p. 67). The fourth part then develops this notion of creative software, especially the near-monopoly of the Adobe suite, which has created a production chain that drives all designers’ practices. The graphic chain thus gradually narrows to a single actor who concentrates all power in a pyramidal scheme. (p. 70). Adobe has become a kind of creative factory in which everyone uses the same tools with a logic of productivity in the field of creation, but also in finding clients through its Behance platform [web platform, a kind of portfolio where Creative Cloud users can present their creations]. This creates dependency, especially through education, where the Adobe suite is favoured. This is all the more harmful as access to software requires a subscription, and the files created with it do not use open formats, so only Adobe tools can open them, which leads to a need for everyone to submit to the creative suite.

Finally, if design gets too deeply caught up in innovation as well as creativity, it risks closing in and no longer being meaningful for us. Instead, as human beings and designers, it would be better to design objects and technical systems that are more open, freer and better shared, through open-source approaches and free access to techniques as well as knowledge.

Another interesting fact, this time concerning the sale of the book itself: there was no problem with sales, despite a free licence that effectively made the text freely accessible. In the same way, even though his thesis was under a free licence, a publisher approached him to publish it, and the stock sold out in less than a year, leading to a new print run. It thus seems that in addition to being beneficial for practice, free licences do not prevent the sale of products.

Git managed to stand out through a decentralised, peer-to-peer approach that fits with the free/libre approach. It has been the most used version control software since 2016.

39 — GitLab is a collaborative text management system created in 2011 by Dmitriy Zaporozhets and Valery Sizov. It aims to simplify development and collaboration on Git projects. GitHub, created in 2008 and acquired by Microsoft in 2018, is another similar platform. GitHub’s source code is completely closed, whereas GitLab has a self-hostable open source version, but also a second one with a proprietary layer that is the web client version.

41 — Visual Culture is a free/libre versioning project based on Git and adapted for the visual. It was presented in 2014 by the OSP collective in the form of a crowdfunding campaign that was unsuccessful. The project was already developed in-house and is now an integral part of the OSP website. Visual Culture presents the complete directory tree of each OSP project, with a temporal visualisation of the modifications made. We can also get an overview of the images used in a project—something standard GitLab or GitHub overviews do not provide. Project visuals are available on the following page.
